# JYSV HERA 0.2.4 — 2026-10-28

백로그나 열린 세션에서 바로 멀티 에이전트 작업을 시작하고, 받은 파일이 진짜인지 직접 확인할 수 있습니다.

### 추가한 것

- **`hera` 를 치지 않는 멀티 에이전트 작업.** 할 일에 마우스를 올려 ▶ 를 누르거나, 할 일 입력칸에 요청을 적고 옆의 팀 버튼을 누르면 고를 수 있습니다: 열린 에이전트 세션이 대화를 이어 가며 이끌기(프로젝트에 열린 다른 에이전트가 보조가 됨), 팀을 새로 시작, 또는 한 에이전트에게만 맡기기. HERA 가 화면을 나란히 열고, 모든 에이전트가 준비될 때까지 기다렸다가 메인에게 보조 구성과 협업 방법을 알려 주고 작업을 넘깁니다. 할 일에는 어느 세션이 진행 중인지 표시됩니다.
- **열린 세션에 보조 붙이기.** 탭 줄의 팀 버튼으로 지금 보고 있는 에이전트 세션 옆에 보조를 엽니다. 대화는 그대로 두고, 그 세션에 협업 방법을 알려 줍니다.
- **자동 회신.** `hera send` 로 일을 받은 에이전트가 회신 없이 끝나면, 20초 동안 조용한 것을 확인한 뒤 HERA 가 그 마지막 화면을 보낸 쪽에 대신 보냅니다. 보조가 승인을 기다리면 메인에게 알립니다. 사용자가 결과를 옮겨 줄 필요가 없습니다.
- **빌드 출처 증명.** 릴리스 파일마다 Sigstore 로 서명한 빌드 출처 증명이 붙습니다. `gh attestation verify <파일> --repo jysvai/JYSV-HERA` 로 이 저장소의 GitHub Actions 가 태그된 소스에서 만든 파일인지 확인할 수 있습니다.
- **잠긴 런타임.** 설치된 앱은 `NODE_OPTIONS` 와 `--inspect` 를 무시하고, 무결성을 확인한 자기 `app.asar` 에서만 코드를 읽습니다(Electron fuses). 설치된 파일을 고치면 실행을 거부합니다.
- **코드 서명 준비.** Windows(SignPath Foundation)와 macOS(Developer ID · 공증) 서명이 릴리스 워크플로에 연결돼 있어서, 인증서를 등록하면 그 릴리스부터 서명됩니다. 그때까지는 Windows SmartScreen 과 macOS 의 첫 실행 확인이 전처럼 나옵니다.
- **보안 검사.** 푸시마다 CodeQL 보안 검사와, 앱에 들어가는 의존성의 `npm audit` 을 돌립니다. 취약점은 저장소의 *Security → Report a vulnerability* 로 비공개로 알릴 수 있습니다.

### 고친 것

- **오른쪽 패널 탭 글자가 두 줄로 밀리던 문제.** “백로그 · 폴더 · 사용량 · Lanes” 가 한 줄에 들어가고, 넘치면 줄바꿈 대신 옆으로 넘깁니다.
- **업데이트 뒤에도 바탕화면 · 시작 메뉴 아이콘이 예전 그림으로 남던 문제.** 설치가 끝나면 Windows 아이콘 캐시를 새로 고칩니다.
