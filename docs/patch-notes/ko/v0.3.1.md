# JYSV HERA 0.3.1 — 2026-10-29

작업 공간의 버그를 고쳤습니다. 작업을 잃을 수 있던 경우가 가장 중요합니다. [작업 공간 안내](../../ko/worktrees.md) 에는 움직이는 그림을 넣었습니다.

### 고친 것

- **작업 공간을 지울 때 합치지 않은 커밋이 경고 없이 사라질 수 있던 문제.** 폴더를 직접 지웠거나 git 이 상태를 알려 주지 못하면, 사라질 것이 없다고 보고 브랜치까지 지웠습니다. 이제 지우기 직전에 저장소에서 다시 셉니다. 셀 수 없으면 작업이 사라질 수 있다고 알립니다.
- **합친 뒤 "지울까요?" 에서 그사이 AI 가 쓴 것을 세지 않던 문제.** 합치는 동안 AI 가 더 쓴 파일이 있으면 그 수도 알립니다.
- **하나로 합치기(squash) 뒤 이어서 한 일을 다시 합치면 충돌하던 문제.** 다음 합치기에는 그 뒤에 한 일만 들어갑니다. 하나로 합친 뒤에는 HERA 가 프로젝트 브랜치를 작업 공간에도 합쳐 둡니다.
- **작업 공간 폴더가 사라진 탭을 다시 열면 AI 가 프로젝트 폴더에서 열리던 문제.** AI 가 실제 프로젝트를 고칠 수 있었습니다. 이제 AI 없이 터미널로 열고, 왜 그런지 알려 줍니다.
- **AI 가 작업 공간 안에서 다른 브랜치로 바꾸면 합치기가 엉뚱하게 동작하던 문제.** 이제 원래 브랜치로 돌아가라고 알려 줍니다.
- **AI 가 아직 일하는 중에 합치면 쓰다 만 파일이 들어가던 문제.** 이제 먼저 묻습니다.
- **여러 AI 비교가 시작하다 실패하면 작업 공간과 탭이 남던 문제.** 만든 것을 모두 되돌립니다.
- **합친 뒤에도 백로그의 "마지막 변경" 이 이전 커밋으로 남던 문제.**
- **합치기 메뉴에 이전 브랜치 이름이 남던 문제.** 터미널에서 프로젝트 폴더의 브랜치를 바꾼 경우입니다.
- **git 오류 메시지에 실행한 명령 전체가 보이던 문제.** 다른 언어로 설정된 git 에서 바뀐 줄 수가 0 으로 나오던 문제도 고쳤습니다.
- **커밋 훅이 있는 프로젝트에서 합치기가 막히던 문제.** 작업 공간의 변경을 자동으로 커밋할 때 걸렸습니다.
- **작업 공간을 만들다 실패하면 이미 있던 브랜치를 지울 수 있던 문제.** 대소문자만 다른 이름일 때입니다.
- **작업 공간 이름이 Windows 예약 이름(con, nul 등)이면 만들지 못하던 문제.**
- **`.worktreeinclude` 에 큰 폴더를 적으면 복사하는 동안 창이 멈추던 문제.**
- **영어 화면의 단어 오류.** 작업 공간 탭 이름이 "Worktree" 로 나오고, "1 sessions" 처럼 복수형이 틀렸습니다.
- CodeQL 이 찾은 파일 읽기 경쟁 상태 4건을 고쳤습니다.

### 바뀐 것

- 프로젝트 폴더가 브랜치에 있지 않으면(detached HEAD) 작업 공간 탭에서 미리 알려 줍니다.
- 앱 자체 시험에 두 경우를 더했습니다. 폴더가 지워진 작업 공간을 지울 때 묻는지, 두 번째 squash 합치기가 프로젝트의 다른 작업을 지우지 않고 되는지 확인합니다.
