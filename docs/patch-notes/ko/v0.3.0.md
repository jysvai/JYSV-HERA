# JYSV HERA 0.3.0 — 2026-10-29

**작업 공간**이 생겼습니다. AI 가 프로젝트의 격리된 복사본에서 자기 브랜치로 일하고, 끝나면 바뀐 것을 보고 합치거나 버립니다. 여러 AI 에게 같은 일을 시키고 가장 좋은 결과를 고를 수도 있습니다.

### 새로 생긴 것

- **작업 공간** (오른쪽 패널의 작업 공간 탭). [안내](../../ko/worktrees.md)
  - 이름을 적고 만들면 `hera/<이름>` 브랜치와 `~/hera-worktrees/<프로젝트>/<이름>` 폴더가 생기고, 그 안에서 AI 나 터미널이 열립니다. 일하는 동안 프로젝트 폴더는 그대로입니다.
  - 카드마다 바뀐 파일 수, 추가·삭제 줄 수, 커밋 수, 커밋하지 않은 파일 수가 보입니다.
  - **변경 보기**: 바뀐 파일을 색으로 구분해 보여 줍니다. 새 파일도 포함합니다. 아래에 메모를 적으면 그 작업 공간의 AI 에게 바로 전달됩니다.
  - **합치기**: 커밋 기록을 남기는 merge, 또는 커밋 하나로 합치는 squash. 충돌이 나면 합치기를 완전히 되돌리고, 충돌 해결을 그 AI 에게 맡길지 묻습니다.
  - **버리기 / 지우기**: 커밋하지 않은 파일과 합치지 않은 커밋이 사라지면 먼저 몇 개인지 알려 줍니다. HERA 는 자기가 만든 작업 공간과 `hera/…` 브랜치만 지웁니다.
- **여러 AI 에게 같은 일 시키고 고르기.** AI 2~4개가 각자 작업 공간에서 나란히 일합니다. 결과를 비교하고 **이걸로 고르기** 를 누르면 그 결과만 합쳐지고, 나머지는 지울지 묻습니다.
- **보조는 각자 작업 공간에서.** 멀티 에이전트 메뉴에서 켜면 새 보조가 각자의 작업 공간에서 열립니다. 메인 에이전트는 각 보조의 폴더와 브랜치, 그리고 결과를 확인하고 가져오는 방법을 브리핑으로 받습니다.
- **처음 쓰는 사람을 위해**
  - git 저장소가 아닌 폴더도 **git 저장소로 만들기** 버튼 하나로 준비됩니다. `.gitignore` 가 없으면 기본 파일을 먼저 만듭니다.
  - 프로젝트의 `.env` 파일을 새 작업 공간에 복사합니다. 더 복사할 파일은 `.worktreeinclude` 에 적습니다.
  - 프로젝트 설정의 **새 작업 공간 준비 명령** (예: `npm install`) 을 새 작업 공간마다 실행합니다.
- **`hera` CLI**: `hera spawn <에이전트> --worktree[=이름]` 은 보조를 자기 작업 공간에서 엽니다. `hera worktrees` 는 이 프로젝트의 작업 공간을 보여 줍니다.

### 바뀐 것

- 작업 공간 안의 폴더는 그 프로젝트로 셉니다. 사용량 페이지, `hera host`, lanes 에 적용됩니다.
- 탭에 브랜치 아이콘이 붙고, 분할 화면에서는 칸 위에 브랜치 이름이 보입니다.
- 앱 자체 시험이 매 릴리스마다 Windows, macOS, Linux 에서 작업 공간 전체 흐름(만들기, 변경 집계, 합치기, 충돌 되돌리기, 지우기)을 확인합니다.
