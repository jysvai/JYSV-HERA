# 작업 공간

작업 공간은 프로젝트의 격리된 복사본입니다. AI 가 그 안에서 자기 브랜치로 일하므로, 일하는 동안 프로젝트 폴더는 바뀌지 않습니다. 일이 끝나면 무엇이 바뀌었는지 보고 프로젝트에 합치거나 버립니다. AI 여러 개가 각자의 복사본에서 동시에 일할 수 있고, 같은 파일을 고쳐도 서로 부딪히지 않습니다.

HERA 는 이 복사본을 git 으로 만듭니다 (`git worktree`). 오른쪽 패널의 **작업 공간** 탭을 여세요.

## 필요한 것

- 컴퓨터에 **git** 이 설치되어 있어야 합니다.
- 프로젝트가 **커밋이 하나 이상 있는 git 저장소**여야 합니다. 아니라면 작업 공간 탭이 그렇다고 알려 주고 **git 저장소로 만들기** 버튼을 보여 줍니다. 이 버튼은 `git init` 을 하고 지금 파일을 첫 커밋으로 저장합니다. 폴더에 `.gitignore` 가 없으면 `node_modules`, `.venv`, `.env` 같은 것을 빼는 기본 `.gitignore` 를 먼저 만듭니다.
- WSL 셸을 쓰는 프로젝트는 아직 지원하지 않습니다.

git 이 이름과 이메일을 모른다고 하면, 아무 터미널에서 아래를 한 번 실행하고 다시 하세요.

```
git config --global user.name "이름"
git config --global user.email "you@example.com"
```

## 작업 공간 만들기

작업 공간 탭에 이름을 적고 (예: *로그인 버그 수정*) **만들기** 를 누른 뒤 AI 나 터미널을 고르세요. HERA 는 다음을 합니다.

1. 프로젝트 폴더의 지금 커밋에서 `hera/<이름>` 브랜치를 만듭니다.
2. 그 브랜치를 프로젝트 밖의 `~/hera-worktrees/<프로젝트>/<이름>` 에 꺼냅니다.
3. 프로젝트의 `.env` 파일들을 복사합니다. git 에는 없지만 보통 프로젝트를 돌리는 데 필요합니다.
4. 그 폴더에서 AI 나 터미널을 엽니다. 탭에 브랜치 아이콘이 붙고, 분할 화면에서는 칸 위에 브랜치 이름이 보입니다.

알아 둘 것:

- 복사본은 **마지막 커밋**에서 시작합니다. 프로젝트 폴더에서 커밋하지 않은 변경은 들어가지 않으며, 탭에 그 개수가 나옵니다.
- `node_modules` 같은 의존성은 복사하지 않습니다. 프로젝트 설정의 **새 작업 공간 준비 명령** 에 (예: `npm install`) 적어 두면 새 작업 공간마다 터미널 탭에서 실행합니다. AI 에게 설치하라고 해도 됩니다.
- 새 작업 공간마다 더 복사할 무시된 파일이 있으면, 저장소 맨 위의 `.worktreeinclude` 파일에 한 줄에 하나씩 경로를 적으세요. 와일드카드는 쓸 수 없습니다 (Orca 와 같은 파일 이름과 규칙).
- AI 가 새 폴더에서 처음 시작하면 그 폴더를 믿을지 물을 수 있습니다.

## 검토하고, 합치고, 버리기

작업 공간마다 카드가 하나씩 있고, 브랜치와 바뀐 내용이 보입니다: 파일 수, `+추가 −삭제` 줄 수, 커밋 수, 아직 커밋하지 않은 파일 수. 숫자는 몇 초마다 새로 고쳐집니다.

- **열기**: 이미 그 안에서 일하는 탭으로 가거나, 그 폴더에서 새 터미널이나 AI 를 엽니다.
- **변경 보기**: 시작한 커밋과 비교해 바뀐 파일을 모두 보여 줍니다. 커밋했든 안 했든, 새 파일도 포함합니다. 아래에 메모를 적고 **보내기** 를 누르면 그 작업 공간의 AI 에게 입력됩니다. 검토하다가 바로 고쳐 달라고 할 수 있습니다.
- **합치기**: 프로젝트 폴더가 있는 브랜치로 합칩니다.
  - **합치기 (merge)** 는 복사본의 커밋 기록을 그대로 둡니다.
  - **하나로 합치기 (squash)** 는 변경 전체를 커밋 하나로 가져옵니다.
  - AI 가 커밋하지 않은 것은 먼저 복사본에 커밋됩니다.
  - 프로젝트 폴더는 브랜치에 있어야 하고 커밋하지 않은 변경이 없어야 합니다. 그래야 실패한 합치기를 언제나 완전히 되돌릴 수 있습니다.
  - **충돌이 나면** HERA 가 합치기를 되돌리고, 프로젝트 폴더는 전과 똑같습니다. 그리고 그 충돌을 복사본의 AI 에게 맡길지 묻습니다. AI 는 복사본 안에서 프로젝트 브랜치를 `git merge` 하고 충돌을 해결한 뒤 커밋합니다. 그다음 다시 합치면 됩니다.
- **⋯ → 변경을 커밋으로 저장**: AI 가 커밋하지 않고 남긴 것을 복사본 브랜치에 커밋합니다.
- **⋯ → 버리기 / 지우기**: 폴더와 `hera/…` 브랜치를 지웁니다. 지우기 전에 커밋하지 않은 파일과 합치지 않은 커밋이 몇 개 사라지는지 먼저 알려 주고, 그 안에서 열린 탭을 닫습니다.

HERA 는 자기가 만든 작업 공간과 `hera/…` 브랜치만 지웁니다. 직접 지운 복사본은 다음에 켤 때 목록에서 사라집니다.

## 여러 AI 에게 같은 일 시키고 고르기

**여러 AI 에게 같은 일 시키고 고르기…** 는 작업 공간 탭과 백로그의 ▶ 메뉴에 있습니다.

1. 맡길 일을 적고 AI 를 2~4개 고릅니다. 같은 AI 를 두 번 골라도 됩니다.
2. HERA 가 AI 마다 작업 공간을 하나씩 만들고, 나란히 띄운 뒤, 각 AI 가 준비되는 대로 일을 입력합니다.
3. 카드는 **비교: …** 아래에 함께 모입니다. 각자의 변경을 보고, 고칠 점이 있으면 메모를 보내세요.
4. 가장 좋은 결과에서 **이걸로 고르기** 를 누릅니다. HERA 가 그 결과를 커밋 하나로 합치고, 이 비교의 작업 공간을 지울지 묻습니다.

AI 마다 자기 사용량을 쓰므로, 비교 한 번에 AI 수만큼 돌린 셈입니다.

## 보조를 각자 작업 공간에서

멀티 에이전트 작업 (백로그의 ▶ 메뉴, 또는 탭 줄의 팀 버튼) 에서 **보조는 각자 작업 공간에서** 를 켜세요. 새로 여는 보조가 각자의 작업 공간에서 열립니다. 메인 에이전트는 브리핑에서 세 가지를 듣습니다. 각 보조가 어느 폴더, 어느 브랜치에서 일하는지, 보조의 결과는 `git diff` 로 확인하라는 것, 그리고 `git merge hera/<이름>` 으로 가져오라는 것입니다. 메인은 프로젝트 폴더에 그대로 있습니다.

에이전트도 [`hera` CLI](hera-cli.md) 로 직접 할 수 있습니다.

```
hera spawn codex --worktree            # 자기 작업 공간에서 일하는 보조 (브랜치 hera/codex)
hera spawn claude --worktree=refactor  # 이름을 정해서
hera worktrees                         # 이 프로젝트의 작업 공간: 브랜치, 폴더, 탭
```

## 어디에 있나

- 작업 공간: `~/hera-worktrees/<프로젝트>/<이름>`. 다른 폴더를 쓰려면 HERA 를 켜기 전에 환경 변수 `HERA_WORKTREES` 를 설정하세요.
- HERA 가 기억하는 목록: HERA 데이터 폴더의 `worktrees.json`.
- 작업 공간에서 쓴 사용량은 사용량 페이지에서 그 프로젝트로 셉니다.
