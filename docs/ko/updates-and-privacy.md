# 업데이트와 개인정보

## 버전

설치된 버전은 사이드바 아래와 설정 맨 위(“JYSV HERA v0.2.1”)에 나옵니다. 터미널에서는 `hera --version`.

## 업데이트 확인

HERA 는 스스로 업데이트하지 않고, 새 릴리스가 있다는 것만 알려 줍니다.

- 시작 약 20초 뒤, 그리고 몇 시간에 한 번 GitHub 의 `jysvai/JYSV-HERA` 최신 릴리스를 조회합니다 (공개 릴리스 API 요청 1건). 마지막 확인이 6시간이 안 됐으면 다시 요청하지 않습니다.
- 새 버전이 있으면 사이드바의 버전 표시가 업데이트 버튼으로 바뀌고, 설정에 “새 버전 vX.Y.Z 이 나왔습니다.” 와 **릴리스 페이지 열기** 가 나옵니다. 내려받아 설치하는 것은 직접 합니다.
- **지금 확인** 은 바로 확인합니다. 확인이 실패하면 마지막 정상 결과를 유지하고 오류를 보여 줍니다.
- 설정의 **새 버전 자동 확인** 을 끄면 자동 확인이 멈춥니다. 이것이 HERA 가 하는 유일한 네트워크 요청이며, 끄면 아무 데도 접속하지 않습니다.

**패치노트** 버튼은 내 버전(새 버전이 있으면 그 버전)의 패치노트를 GitHub 에서 엽니다. 파일은 저장소의 `docs/patch-notes/en`, `docs/patch-notes/ko` 에 있습니다.

## HERA 가 보내는 것

사용자에 관한 정보는 없습니다. 업데이트 확인은 사용자 에이전트 `JYSV-HERA/<버전>` 으로 보내는 일반 HTTP 요청뿐입니다. 원격 측정, 계정, 분석 도구가 없습니다. 실행하는 에이전트(Claude Code, Codex 등)는 평소처럼 각자의 서비스와 통신하며, 그 통신은 HERA 가 아니라 그 도구의 것입니다. `hera` 명령과 lanes 연동은 로컬 파이프로만 동작합니다.

## 데이터 저장 위치

HERA 데이터 폴더:

| 운영체제 | 위치 |
|---|---|
| Windows | `%APPDATA%\JYSV HERA` |
| macOS | `~/Library/Application Support/JYSV HERA` |
| Linux | `~/.config/JYSV HERA` |

설정 페이지 제목 아래에 정확한 경로가 나옵니다. HERA 를 켜기 전에 환경변수 `HERA_HOME` 을 다른 폴더로 지정하면 그 폴더를 쓰는 별개의 인스턴스로 실행됩니다.

들어 있는 것:

| 파일 · 폴더 | 내용 |
|---|---|
| `config.json` | 설정, 프로젝트, 직접 만든 에이전트, 테마, 팀, 계정 프로필. |
| `sessions.json` | 열린 터미널과 마지막 화면 ([세션 기억](session-memory.md)). |
| `launches.jsonl` | 프로젝트를 언제 무엇으로 실행했는지. |
| `bus.jsonl` | `hera` 메시지 기록 (에이전트 대화 페이지). |
| `mail/` | 긴 `hera` 메시지를 저장한 파일. |
| `usage-cache.json` | 집계한 [사용량](usage.md) 숫자. |
| `claude-caps.json` | 상태줄 연동을 켰을 때 Claude 한도 퍼센트의 최신 값. |
| `claude-settings.backup.json` | HERA 가 Claude Code 설정을 바꾸기 전에 한 번 만든 백업. |
| `cli-token` | `hera` 명령이 앱과 대화하기 위한 무작위 토큰. 본인만 읽을 수 있습니다. |
| `update.json` | 마지막 업데이트 확인 결과. |
| `window.json` | 창 크기와 위치. |
| `shell/` | 셸용으로 생성한 단축어 · 시작 파일. |

사용량과 기록을 위해 읽는 AI 도구의 로그는 각 도구가 둔 자리에 그대로 있으며, HERA 는 읽기만 하고 복사하지 않습니다. 프롬프트 기록 페이지의 프롬프트도 그 로그에서 가져옵니다.

처음부터 다시 시작하려면 HERA 를 종료하고 데이터 폴더를 삭제하거나 이름을 바꾸세요.
