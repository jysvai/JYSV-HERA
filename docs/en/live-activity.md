# Live activity

While AIs work in a project, the top of the **Folders** tab (폴더) shows what they are doing: how far each agent has got, how much of the work each model did, what it would cost at API prices, and which files are being read or changed right now, and by which agent. You see it at a glance without reading every terminal.

![Two agents at work: Claude Code fixes a login bug and starts an Explore subagent on Haiku, Codex edits the login form. The In progress section shows each agent's progress, the share each model did and the files they read and edit; both agents change session.ts, so it turns red. Clicking it opens the tree at that file](../images/live-activity/en-work.gif)

## Where it is

Open the right panel's **Folders** tab (`Ctrl+Shift+E`, `⌘E` on macOS). The **In progress** section (진행 중) sits above the folder tree; click its header to fold it. While an agent in the project is working, the Folders tab shows a dot even when another tab of the panel is open.

Nothing needs turning on. When no agent is at work, the section is one line.

## What it shows

![The In progress section close up: a bar split by model (Opus 47%, gpt-6.1-sol 45%, Haiku 8%) and the estimated cost; a row for claude-1 at 2/3 with its request and the step it is on, its Explore subagent done, codex-1 at 3/3; below, files with a red warning on session.ts, an orange pencil on session.test.ts and a blue eye on client.ts](../images/live-activity/en-panel.png)

### Work per model

The bar at the top splits the current work by model: each model's share of the tokens generated by every agent in the project and the subagents they started. Below it, each model with its share. Models of the same agent share its color in lighter steps, for example Opus and the Haiku subagent it started.

The amount on the right is an estimate at API list prices for Claude models. On a subscription plan you are not billed this way; it tells you how heavy the work is. Codex and other models show no cost.

### One row per agent

- **Name and model**: the tab's name (`claude-1`, `codex-1`, `lane mid`) and the model doing most of its work. Click the row to go to that tab.
- **Progress bar**: from the agent's own to-do list (Claude Code's task list) or plan (Codex's plan). With neither, but with subagents started, it counts how many of them are done. Otherwise the bar moves without a number while the agent works: HERA does not guess a percentage. A finished piece of work turns green.
- **On the right**: steps done out of all steps, or *Working* (작업 중), *Waiting for you* (응답 기다림, the agent asks for approval) or *Done* (완료), and the estimated cost.
- **Under the bar**: the request you gave it, and ▸ the step it is on now.
- **Subagents** a Claude Code agent starts (Explore, a reviewer…) are listed under it with their type, model and task, and turn *Done* when they finish.

Hover a row for the tool calls, files changed and tokens of that work. A new request starts a new piece of work: the numbers start again from zero. Finished work stays on screen for 30 minutes.

The header sums it up: how many agents are working, the overall progress of the agents that made a plan, and the estimated cost.

### Files

| Mark | Meaning | How long it stays |
|---|---|---|
| Blue eye | **Reading** (보는 중): an agent opened the file | 90 seconds after the read |
| Orange pencil | **Editing** (수정 중): an agent changed the file | while that agent works, and 5 minutes after |
| Red warning | **Several agents are editing it**: two different agents changed it during their current work | as long as the edits do |

Each file shows its folder, the lines added and removed (<code>+12 −3</code>), the agents on it (`claude-1 +1` means one more) and how long ago. Click a file being read to open the tree at it; click a changed file to see what changed (below). A file in a [worktree](worktrees.md) copy shows a branch icon; it is not marked in the tree, which shows the project folder.

The tree marks the same files: a colored name and a tint for a file, a dot on a closed folder that holds one.

A red file means two agents are changing the same thing at once, and one may undo the other's work. Let one of them finish, or give the second one its own copy with [Worktrees](worktrees.md).

### What changed and what it affects

Once an agent has changed files, a **Changed files** (바뀐 파일) card shows above the file list: how many files and how many lines were added and removed in the current work. Click it (or a changed file) to open three columns:

![Claude Code edits session.ts and adds errors.ts; the In progress section shows a Changed files card with 2 files, +12 −3. Clicking it opens the dialog: the diff of session.ts, and its impact: three files use it directly, three more through them, and two related tests. Picking errors.ts shows the new file; Ask to check fills in a note with the tests and files to check](../images/live-activity/en-changes.gif)


- **The changed files** of the work shown, all agents together, newest first. A new file has a plus icon, a deleted one a minus.
- **What changed**: each agent's changes to the selected file, line by line (added lines green, removed lines red), with the agent's name and when. **Show in tree** and **Open** take you to the file.
- **Impact** (영향 범위): the files that import the selected one, the files reached through those (up to three steps), and the related tests: tests among them, and tests named after the file (`login.test.ts`, `test_login.py`). Click one to open the tree at it.

At the bottom you can write a note to the tab whose agent changed the file last and send it there. **Ask to check** fills in a note that asks the agent to run the related tests and to check the files that use this one.

The changes come from the agents' own edits: Claude Code's edit and write tools (the patch it records) and Codex's patches (counted when Codex sends them). Lines are counted as made, so a line changed and changed back counts both times. A file changed by a shell command or another program, or a notebook edit, shows in the list without its contents. A change that starts the next request belongs to the next piece of work: the card counts the current one.

The impact comes from import statements, read when you open the dialog:

- TypeScript and JavaScript: relative paths, `import()` and `require`, the `paths` and `baseUrl` of `tsconfig.json` / `jsconfig.json` (with what they `extends` and `references`, and the nearest config above each file in a monorepo), and workspace packages imported by their `package.json` name.
- Python: relative and package imports, also over several lines.

Imports in comments are skipped. It does not see code loaded by a name in a string, or config files that name a file. The files read are the project's source files (`git ls-files`, or the folder without `node_modules`, `dist` and the like), up to 30,000.

## Where the information comes from

HERA reads the conversation logs the agent CLIs already write on your computer. Nothing is installed in the CLIs, no hooks are added, and nothing goes over the network.

- **Claude Code**: `~/.claude/projects/<folder>/<conversation>.jsonl`, and next to it the logs of the subagents it starts. Lanes in HERA tabs count too.
- **Codex**: `~/.codex/sessions/<year>/<month>/<day>/rollout-*.jsonl`.
- With [account profiles](agents.md), the profile's folder instead of `~/.claude` or `~/.codex`.

Only the logs of open agent tabs are read, and only what was added since the last read (every 1.5 seconds while the window is on screen, less often when it is hidden). A long conversation is read from its last 2 MB.

Files are recognized from:

- Claude Code's read and edit tools, and from Codex's patches;
- shell commands that read a file (`cat`, `head`, `sed -n`, `rg … file`, `Get-Content`…) or write one (`>`, `sed -i`, `tee`, `Set-Content`…), in the folder the command ran in.

A file an agent changes through another program (a script, a formatter, `git checkout`) is not seen.

## Limits

- Other agents (Antigravity, Gemini CLI, opencode…) do not show here yet.
- A percentage appears only when the agent made a plan or started subagents.
- The share is by generated tokens, not by time or by lines changed.
- Costs are estimates at API list prices.
- When HERA starts while an agent is already in the middle of a long piece of work, the numbers count from what HERA read.
